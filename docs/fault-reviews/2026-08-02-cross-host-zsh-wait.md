## 1. 问题描述

### 1.1 问题场景

在两个临时 `crdt-sync-probe` 接收端之间运行八个并发发送者时，测试 shell
将后台 PID 追加到 zsh 标量字符串，再用未开启 `SH_WORD_SPLIT` 的展开传给
`wait`。

### 1.2 具体表现

`wait` 将整个 PID 字符串当成一个 job，返回 `job not found`。脚本随后未以该
失败作为终止条件，部分后台发送在 shell 退出前只投递到第一个目标，导致两个测试
端内存状态暂时不一致。该轮结果已明确废弃，未作为性能或正确性证据。

### 1.3 错误信息

```text
zsh:wait: job not found
```

## 2. 临时解决方案

按已记录 PID 停止两个 probe 并确认临时 listener 已消失，随后以同一受限二进制和
一次性 token 重启空状态接收端。没有持久化数据库、快照或业务数据需要修复。

## 3. 根本原因分析

1. 初始状态检查发现两个端的 probe state 不对称，排除了完整收敛。
2. 本地检查没有残留 sender，八个 sender 输出文件为空，说明父 shell 已结束。
3. 失败日志定位到 zsh 对标量变量不做默认空白分词；`wait` 没有获得单独 PID。
4. 脚本没有把任一 `wait` 失败变成最终非零退出，后续读取 state 的成功掩盖了编排
   失败。

直接原因是测试编排使用了标量 PID 列表，而非 zsh 数组。

根本原因是并发测试脚本没有把“所有发送者成功退出”作为读取和断言最终 state 的前置
条件。仓库中的 CRDT 代码未发生故障；问题限于一次性测试驱动。

## 4. 解决方案

改用 zsh 数组保存 PID，并逐项 `wait`：

```zsh
typeset -a pids
pids=()
# 启动 sender 后：pids+=($!)
status=0
for pid in "${pids[@]}"; do
  wait "$pid" || status=1
done
(( status == 0 )) || exit 1
```

只有所有 sender 成功退出后才读取两个 receiver state，并同时断言两端字节相同、
重复投递未增加计数、RGA `pending=0`。修正后的八 sender 测试已通过。

## 5. 预防措施

- [x] 并发 sender 使用 shell 原生数组，禁止依赖未声明的字符串分词规则。
- [x] 所有 `wait` 的退出状态必须在最终 state 断言前聚合并使脚本失败。
- [x] 任何不对称或部分投递状态都必须重启短生命周期 probe 后再测，不得混入证据。
- [ ] 若将测试常态化，提供不含凭据的受控 runner，并在 CI 中覆盖 child-failure、
  timeout 与 cleanup 分支。

## 6. 经验总结

> 并发 CRDT 测试的收敛断言只有在所有发送者都被逐一确认成功退出后才有意义。
